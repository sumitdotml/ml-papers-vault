## Abstract

Instruction tuning enhances large language models (LLMs) by aligning them with hu- man preferences across diverse tasks. Tradi- tional approaches to create instruction tun- ing datasets face serious challenges for low- resource languages due to their dependence on data annotation. This work introduces a novel method, Multilingual Reverse Instruc- tions (MURI), which generates high-quality instruction tuning datasets for low-resource languages without requiring human annota- tors or pre-existing multilingual models. Uti- lizing reverse instructions and a translation pipeline, MURI produces instruction-output pairs from existing human-written texts in low-resource languages. This method en- sures cultural relevance and diversity by sourcing texts from different native domains and applying filters to eliminate inappropri- ate content. Our dataset, MURI-IT, includes more than 2 million instruction-output pairs across 200 languages. Evaluation by native speakers and fine-tuning experiments with mT5 models demonstrate the approach’s ef- fectiveness for both NLU and open-ended generation. We publicly release datasets and models at [https://github.com/akoksal/muri](https://github.com/akoksal/muri).

## Notes: zero-shot

### Main questions

- What is instruction tuning? (Making LLMs follow instructions)
- What are instruction tuning datasets? (Collections of instruction-output pairs)
- Three traditional creation methods (Human, template, synthetic)
- Why each fails for low-resource languages (Cost, lack of data, translation issues)
- The translationese problem (Unnatural translated text)
- Why MURI is different (Uses original text as outputs)

This paper's background starts off with instruction tuning. So instruction tuning mainly refers to making large language models follow instructions. In other words, when we send prompts to the language model, it needs to understand what kind of prompt it is and answer accordingly without going on a loop or a tangent and a long sequence when it doesn't really need to. For instance, if I ask a language model what the capital city of Kenya is and it starts saying something like (just for instance) "oh yes, Kenya is a great country and Kenya has a lot of good things about it. It's a country of great culture and it has some very nice cities and Nairobi is its capital and in this capital you can do this thing and that thing..." - this becomes too long and that's not what we asked. If we do some proper instruction tuning to the large language model, it would have answered with just for instance "Nairobi" or "The capital of Kenya is Nairobi". But instruction tuning goes beyond just being concise - it's also about understanding when to write a detailed analysis versus a quick summary, when to be creative versus factual, and generally aligning with what humans actually want from their AI assistants. So this instruction tuning is possible through instruction tuning datasets. So how this is done normally is that there is basically a pair that has an instruction and an output. The dataset has tons of these pairs and these are used for training the language models. These kinds of datasets are being traditionally created using three methods and these fail for low-resource languages and this is where this paper comes in.

The three traditional creation methods have mainly been human, template and synthetic based approaches towards creating instruction tuning datasets. So for the human based one we just ask humans to help out and that is very costly. But it's not just the cost - imagine trying to find a thousand qualified speakers of Ainu who also understand AI training requirements. The scale is also daunting since we need millions of examples for good performance. For the template based approach, we don't actually use existing instruction datasets - instead we take regular NLP datasets like sentiment analysis or translation pairs and create templates to convert them into instruction format. Like taking "Text: 'Great movie!' Label: Positive" and turning it into "Instruction: Is this review positive? Output: Yes". The problem is that low-resource languages barely have any of these NLP datasets to begin with. And the last one, the synthetic one is when we ask a certain language model to just create the dataset and if we want to use that for let's say a different language we translate whatever has been created. But these three fail miserably for low-resource languages such as let's say Maori or maybe Zulu or Ainu. This affects billions of people since there are about 7,000 languages worldwide but most LLMs only support maybe 50-100 well.

The failures happen mainly because first if we think about the human aspect it's probably difficult to go to humans and just ask them to help out with creating the instruction tuning datasets. Obviously that is costly as well as not too practical when you can't even find enough qualified speakers. And secondly if we want to create maybe template based datasets or synthetic data, we don't have enough data to begin with for the template approach because there simply aren't enough annotated NLP tasks in these languages. And in order to generate synthetic data we have to ask already existing language models which are not very good at this because they were not really trained with these low-resource languages. English dominates 73% of the most popular datasets in the world and there are other major languages that are used for the datasets and not really these low-resource languages. The models literally can't generate quality text in languages they barely know, and when forced to translate, cultural concepts get lost entirely. As a result while creating synthetic datasets or even using templates to translate them into let's say datasets of the targeted low-resource languages these could often result in this one concept called translationese artifacts which include simplified vocabulary and grammar, unidiomatic word order and expressions (meaning they sound wrong and unnatural), and just the linguistic and cultural context are mostly neglected. For example, a direct translation might produce "Please to be describing your most favorite memory of childhood time" instead of how a native speaker would naturally say "Tell me about a favorite childhood memory". These will negatively impact model training in these low-resource languages because the examples get distorted and they feel very unnatural and that is the translationese problem because of these traditional methods of creating instruction tuning datasets.

As a result this paper was introduced to use reverse instructions which effectively helps solve this issue. The clever part is that MURI uses existing human-written text in the target language as the output (which is already natural and culturally appropriate), and only translates the instructions, minimizing the translationese problem while preserving authentic language use.

So the MURI flow is:

1. get the target language output raw text
2. translate it to (say) English
3. ask an LLM what the instruction for this translated text could be (this is reverse-instruction)
4. use the LLM-generated reverse-instruction and then translate this instruction back to the target output language

So basically, we have the authenticity of the target language in the dataset with the attempt at minimizing the translationese artifcats.
